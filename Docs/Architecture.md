# Architecture

How the code is organised, and why, for someone about to change it. [How it plays](Experience.md) describes the behaviour this code produces; this page says where that behaviour lives.

## Four assemblies

| Assembly | Folder | May use | Holds |
|---|---|---|---|
| `MRShowroom` | `Scripts/`, except `MR` and `Editor` | Unity, TextMeshPro, UI, the Input System. No Meta SDK types | The experience: flow, product, panels, hints, audio, analytics |
| `MRShowroom.MR` | `Scripts/MR` | The above, plus Meta XR Core, the Interaction SDK, the MR Utility Kit and the Depth API | Everything that talks to the headset |
| `MRShowroom.Editor` | `Scripts/Editor` | Everything, editor only | The setup pipeline and the builders that generate scenes, prefabs and art |
| `MRShowroom.Tests.PlayMode` | `Tests/PlayMode` | The first two | The play-mode tests |

The core assembly can't see the SDK, and that is deliberate. It means the whole experience runs and is tested in the editor with no headset, and an SDK upgrade touches one folder. The two sides meet in three places:

```
        MRShowroom.MR                                MRShowroom (no SDK types)

  PlacementController ───── Place(pose, surface) ──►  ProductStage
  InteractionGrabBridge ─── BeginHold / EndHold ───►  GrabTarget
  PassthroughController,                              ShowroomEvents
  OcclusionToggle, XRHaptics,  ◄──── events ───────►  (a static hub that audio, hints,
  InputModeWatcher                                     analytics and the flow also use)
```

- **`ProductStage`** is the spot where the product lives. The MR layer decides where that is and calls `Place`. Everything else positions itself from `ProductStage.RestPoint` and never learns how the spot was found.
- **`GrabTarget`** is something that can be picked up. The Interaction SDK reports grabs to it through `InteractionGrabBridge`; the editor's mouse controls report them the same way. Everything above it works alike with hands, controllers or a mouse.
- **`ShowroomEvents`** is a static event hub. Gameplay raises events; audio, haptics, hints, analytics and the MR layer listen, so none of them holds a reference to another.

## Two scenes

**Bootstrap** is nearly empty so the app reaches passthrough quickly. `AppBootstrap` turns off vSync and the frame cap (the headset's compositor paces frames), stops the screen sleeping, and loads Showroom.

**Showroom** holds everything else:

| Object | What is on it |
|---|---|
| `OVRCameraRig` | Meta's camera rig and its full interaction rig: hands, controllers, grab, poke and ray. Locomotion is switched off. Also the passthrough layer |
| `EventSystem` | `PointableCanvasModule`, which turns pokes and rays into UI clicks |
| `Directional Light` | The only light |
| `MixedReality` | `MRUK` (Meta's room-scan reader, told not to load at startup), `EnvironmentDepth` (off until allowed), and `Services`, which carries every script in `Scripts/MR` |
| `Stage` | `ProductStage`, with `RestPoint` (shadow catcher, contact shadow, footprints) and `Pedestal` |
| `Product` | `ProductController`, `ColorCustomizer`, `ExplodeController`. The product itself is instantiated under `Stage/RestPoint` at runtime |
| `PlacementReticle` | The ring shown while placing by hand |
| `UI` | `SwatchPanel`, `EndCard`, `PlacementPanel`, `Hints` |
| `Flow` | `ShowroomFlow`, `HookSequence`, `RevealSequence`, `AnalyticsLogger`, and `Audio` underneath |
| `VirtualStudio` | A grey floor, shown only when there is no passthrough |
| `Debug` | `EditorDesktopControls` and `PerfOverlay` |

Both scenes are generated by `SceneBuilder`. Change the builder and rebuild; don't edit the scenes by hand. See [Conventions](#conventions).

## The flow

`ShowroomFlow` is a small state machine over `ShowroomPhase`: FindSurface, Hook, Inspect, Customise, Explode, Reveal, EndCard, Free.

- `Enter(phase)` switches things on. Because phases can be skipped, each one calls `ShowEverythingUpTo` to make sure what the earlier phases would have switched on is on.
- `Update` decides when a phase is over, from counters fed by events (grabs, colour changes) and the phase timer, against the limits in `ShowroomTuning`.
- `HookSequence` and `RevealSequence` are coroutines that animate the product in code and raise `Finished`. Both switch the product's return spring off while they run and back on afterwards.
- `Advance()` and `Restart()` exist for the editor's debug keys, the tests and **Play again**.

The phase timer and both sequences use scaled time, so they stop while the app is paused.

|---|---|---|

| `ColorChanged`, `FinishChanged` | `ColorCustomizer` | `ShowroomFlow`, `GuideHints` (colour only), `AnalyticsLogger` |
| `Exploded`, `Reassembled` | `ExplodeController` | `OcclusionToggle`; `Exploded` also by `ShowroomFlow`, `GuideHints`, `AnalyticsLogger` |
| `HotspotOpened` | `HotspotView` | `GuideHints`, `AnalyticsLogger` |
| `CtaPressed` | `EndCardController` | `ShowroomFlow` (Play again), `AnalyticsLogger` |
| `InputModeChanged` | `InputModeWatcher` | `PlacementPanel`, `AnalyticsLogger` |
| `SfxRequested` | Whatever made the sound | `AudioDirector`, `XRHaptics` |

The last row runs the other way: the UI asks, the MR layer answers. Static events are cleared on every play-mode start, so nothing leaks between runs with domain reload switched off.

## Placement

```
PlacementController ──► SurfaceFinder ──► SurfaceMath        ProductStage
 (the order of           (asks MRUK and     (pure geometry,   (where the result
  fallbacks, the          the depth sensor)  no SDK types)      is applied)
  permission, the anchor)
```

- `PlacementController` owns the order of fallbacks set out in [How it plays](Experience.md#finding-a-surface), the permission request, the spatial anchor, and following the user. It waits for a tracked head and for `PassthroughController` before placing anything.
- `SurfaceFinder` loads the room through MRUK, describes each table anchor as a flat rectangle, finds a free spot on the floor, and raycasts against the scanned room or, without one, the depth sensor. The table search runs once per placement, never per frame.
- `SurfaceMath` chooses the table and the point on it. It has no SDK types, so its rules are unit tested.
- `ScenePermission` asks for the spatial data permission itself and gets a callback either way. OVRManager's "request on startup" option is left off on purpose: it gives no callback on refusal, and a second request made while its dialog is open fails silently.
- `RoomLighting` aims the light from the nearest window the scan knows about, but never so far round that the side the user is looking at falls into shade.

`SurfaceInfo` carries the result to the stage: the method used, how much free room the surface has (the reveal walk sizes its loop from this) and the pedestal height.

## The product

A product is data plus a prefab. Nothing in the code names the AERO Pulse.

- **`ProductDefinition`** is a ScriptableObject holding everything about one product. [Products](Products.md) documents its fields.
- **`ProductView`** sits on the prefab root and describes how the prefab is put together: `root > Visual > one slot per part > the part's body`. The exploded view moves the slots. A part that is picked up moves its body, which springs back to its slot.
- **`ProductController`** instantiates the prefab under the stage's rest point, hands it to the customiser and the exploded view, creates the hotspots, and applies one rule for what can be grabbed: the whole product while it is together, its parts while it is fully apart, nothing in between.
- **`ReturnToRest`** is a damped spring back to a pose local to the parent. Nothing is driven by physics. Bodies are kinematic, so a released product glides home instead of falling.
- **`ColorCustomizer`** makes one material instance per source material and drives the tint properties of the Product Lit shader. A colour change sets a "from" colour, a "to" colour and a sweep position per region, and the shader draws the moving edge between them.
- **`ExplodeController`** moves each slot along the direction authored for it, watches for the pull and push gestures through `GrabTarget.HoldSpread`, and lays out the labels each frame they are showing.
- **`HotspotView`** is a world-space canvas whose origin is the dot. Its card floats in front of the product as the viewer sees it, so a dot on the far side never opens a card inside the model.

## Panels

The panels are world-space canvases authored in millimetres and scaled by 0.001, so a font size of 20 is 20 mm tall. They are built entirely in code by `SceneBuilder`.

- `PanelFader` shows and hides a panel, and makes sure a hidden one can't be seen, poked or pointed at.
- `DockedPanel` keeps a panel beside the product, on the dominant side or the opposite one, facing the user. It re-aims only after the user has moved a quarter of a metre, so it holds still while they lean in to press it.
- `SwatchPanelController` fills the colour panel from the product definition. A product with fewer regions, colours or presets hides the buttons it doesn't need.
- `GuideHints` shows the prompt and poses the ghost hands. The hands are the Interaction SDK's own hand model, posed in code.

Poke and ray support is added to each canvas with the Interaction SDK's quick actions. Every panel background, button, swatch and chip is the same disc sprite, sliced to whatever corner radius it needs, on one material.

## Rendering in mixed reality

Passthrough is an underlay: the headset shows the real room wherever the frame's alpha is zero. Three rules follow.

1. The eye camera clears to transparent black. `PassthroughController` sets this, and falls back to a solid colour and the virtual studio where there is no passthrough.
2. Transparent materials must accumulate alpha, with `Blend SrcAlpha OneMinusSrcAlpha, One OneMinusSrcAlpha`. With the stock blend a translucent panel goes hazy against the room. That is why the UI has its own shader.
3. Only the product and its shadow test against the real room's depth. Occlusion costs GPU time, so the UI doesn't pay for it.

| Shader | Used for | Notes |
|---|---|---|
| `MRShowroom/Product Lit` | The product | URP lighting, three tint regions, the colour sweep, the hover rim and depth occlusion |
| `MRShowroom/Shadow Catcher` | The invisible plane under the product | Shows only the shadow that falls on it, as a darkening of the real table |
| `MRShowroom/UI Panel` | Every panel | The stock UI shader with the alpha rule above |
| `MRShowroom/Ghost` | Hint hands | A depth prepass, so fingers don't show through each other |
| `MRShowroom/Callout` | Part-label lines and dots | Drawn over everything, so a line can be followed to its part |

Lighting is one soft directional light and a flat ambient term. Its shadow is the only real-time shadow, and it lands on the shadow catcher. On a pedestal the shadow catcher is off and the pedestal receives the shadow like any other object. URP runs with 4x MSAA and no HDR, post-processing, depth texture or opaque texture.

`OcclusionToggle` switches the Depth API on once the headset supports it and the user has allowed spatial data. It can switch it off again while the product is apart, if that moment turns out to be over the frame budget. `XRDisplaySetup` asks for 90 Hz, falling back to 72, and for medium fixed foveation with dynamic foveation.

## Running without a headset

- `VirtualStudio` shows a grey floor whenever passthrough isn't active, and `ProductStage` draws the pedestal as a stand-in for the table.
- `EditorDesktopControls` turns the mouse and keyboard into a head and a hand. It grabs through `GrabTarget`, exactly as the SDK bridge does.
- The camera rig is never moved to fake a head. Its tracking space has to stay on the floor origin, because that is what a room, scanned or sample, is positioned against. The pretend head lives in `DesktopHead`, and `EditorHeadEmulation` applies it to the eye anchors.
- `SurfaceFinder` can load one of MRUK's sample rooms in place of a scan. Its `Editor Room` field, on `MixedReality/Services` in the Showroom scene, chooses which: 0 is an office with one desk, 1 a living room with more than one table, 2 a bedroom with none, and -1 loads no room at all.
- `PlayFromBootstrap` makes Play start from the Bootstrap scene whichever project scene is open.

All of this is compiled out of builds or does nothing once a headset is active.

## Pause, sound and haptics

- `PauseService` sets the time scale to zero and pauses audio while the headset is off, the Meta menu is open or the system has paused the app. The reasons stack.
- `AudioDirector` plays effects through six spatial voices, from the position each event reports, and fades the music bed in under the hook and the end card.
- `XRHaptics` turns the same events into short controller pulses, and does nothing with bare hands.

## Analytics

`AnalyticsLogger` listens to the events and writes one JSON file per run to `Application.persistentDataPath/analytics`. Nothing is sent anywhere. **Play again** closes the file and starts a new one, so each pass through the flow is its own record.

```json
{
  "sessionId": "3f6c1e0a9b7d4c2e8a5f0b1d2c3e4f5a",
  "startedUtc": "2026-10-04T09:12:44.0000000Z",
  "appVersion": "0.1.0",
  "device": "Oculus Quest",
  "product": "aero-pulse",
  "inputMode": "Hands",
  "placement": "Table",
  "secondsToPlacement": 2.1,
  "totalSeconds": 74.3,
  "phases": [ { "phase": "FindSurface", "seconds": 2.1 }, { "phase": "Hook", "seconds": 4.7 } ],
  "reachedEndCard": true,
  "grabs": 3,
  "hotspotsOpened": 2,
  "colorChanges": 4,
  "finishChanges": 1,
  "colorway": "Custom",
  "finish": "Metallic",
  "finalColors": [ { "slot": "Upper", "color": "Graphite" } ],
  "explodeByGesture": 1,
  "explodeByButton": 0,
  "explodeByGuide": 0,
  "buyNow": 1,
  "share": 0,
  "playAgain": 0
}
```

The values above are made up to show the shape. `phases` has one entry per phase and `finalColors` one per colour region. `explodeByGuide` counts the times the app had to open the exploded view for a user who never tried, which is the number to watch when judging whether the gesture is discoverable.

The file is written when the user reaches the end card, on every end-card button, when the app is paused and when it closes. The same JSON goes to the log on a line starting `[Analytics]`, which also gives the exact path. On the headset that is normally:

```sh
adb pull /sdcard/Android/data/com.alihamza.mrshowroom/files/analytics
```

## Conventions

- **Scenes and prefabs are generated.** `SceneBuilder`, `ProductAssetBuilder`, `ProductPrefabBuilder`, `HintAssetBuilder` and `BrandAssetBuilder` create them from code, so they can be recreated at any time and reviewed as code. A value you see on a scene object comes from a field initialiser in its script or from the builder. Change it there and rebuild, because an edit made in the inspector is lost at the next rebuild.
- **Data assets are kept.** The product definition, the brand theme, the tuning asset, materials and textures are created once and never overwritten, so values tuned in the inspector survive a rebuild.
- **`Wire`** sets private serialized fields by name and throws when a name is wrong, so a renamed field can't silently leave a reference empty.
- **`SceneBuilder.ContentVersion`** is raised when the builders change in a way existing scenes need. A project built by an older version is offered a rebuild when it is opened.
- **Comments explain why, not what,** and every class has a summary.

### Where to change what

| To change | Look at |
|---|---|
| Pacing, reach, thresholds | `Data/ShowroomTuning.asset` |
| The product's colours, hotspots, parts, price | `Data/Products/AeroPulse.asset` |
| Brand colours, logo, sounds | `Data/Themes/Aero.asset` |
| What a phase switches on, and when it ends | `ShowroomFlow.Enter` and `ShowroomFlow.Update` |
| Which table is chosen, and where on it | `SurfaceMath`, with the placement values in the tuning asset |
| The order of placement fallbacks | `PlacementController` |
| Prompt and button wording | The field initialisers in `GuideHints`, `PlacementPanel`, `EndCardController` and `SwatchPanelController`, then rebuild |
| Panel layout | `SceneBuilder.BuildSwatchPanel`, `BuildEndCard` and `BuildPlacementPanel`, then rebuild |
| Project settings | `ProjectConfigurator` |
